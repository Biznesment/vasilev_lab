# Место — PWA для Android

Небольшое приложение с белым фоном, боковым меню и каталогом [GitHub Emoji](https://api.github.com/emojis). Работает без сборки и внешних библиотек; нужен Node.js 18+.

## Запуск на компьютере

```sh
npm start
```

Откройте <http://localhost:8000>. `localhost` считается защищённым контекстом для Service Worker. При открытии **с телефона по сетевому IP** обычный HTTP не подходит — используйте HTTPS ниже. Адрес и порт можно изменить переменными `HOST` и `PORT`.

## Установка на Android по локальной сети

Компьютер и телефон должны быть в одной Wi-Fi-сети. Узнайте локальный IPv4 компьютера (например, `192.168.1.45`, в Windows — `ipconfig`, в Linux — `ip addr`, в macOS — настройки сети). Подставьте свой адрес во все примеры. При необходимости разрешите входящие подключения на порт 8000 в файрволе.

1. Создайте собственный CA и сертификат сервера с правильными SAN. Требуется OpenSSL:

   ```sh
   ./scripts/create-certs.sh 192.168.1.45
   # Необязательно: добавьте вторым аргументом имя, по которому телефон действительно может найти компьютер:
   # ./scripts/create-certs.sh 192.168.1.45 computer.local
   ```

   Скрипт создаёт `certs/ca.crt`, `certs/ca.key`, `certs/server.crt`, `certs/server.key`. Если файлы уже есть, он не перезаписывает их. Для другого IP/имени сохраните или удалите старый каталог `certs` и создайте сертификаты заново. Каталог исключён из Git. **Не передавайте приватные ключи** `ca.key` и `server.key` и не публикуйте их в интернете.
2. Безопасно перенесите **только** `certs/ca.crt` на Android и установите его как сертификат центра сертификации. Путь зависит от версии Android, обычно: «Настройки → Безопасность → Шифрование и учетные данные → Установить сертификат → Сертификат ЦС». Может понадобиться блокировка экрана. Устанавливайте лишь свой CA на устройства, которым вы доверяете; после проверки его можно удалить из пользовательских сертификатов. Если Chrome или версия Android не доверяет пользовательскому CA, потребуется другой доверенный сертификат либо устройство/конфигурация, в которой доверие поддерживается.
3. Запустите HTTPS-сервер из каталога проекта:

   ```sh
   npm run https
   ```

   Встроенный сервер не отдаёт каталог `certs`. При необходимости можно указать другие файлы через переменные `TLS_KEY` и `TLS_CERT`.
4. В Chrome на телефоне откройте **`https://192.168.1.45:8000/`**, заменив IP на свой. IP в адресе обязан совпадать с SAN сертификата. Если используется `computer.local`, имя также должно быть в SAN и разрешаться на телефоне; не все сети поддерживают mDNS. Не используйте `10.0.2.2` в качестве адреса установки на эмуляторе. Для эмулятора отдельно проверьте доступность выбранного адреса локальной сети и доверие к CA внутри эмулятора.
5. Когда Chrome сочтёт приложение устанавливаемым и отправит `beforeinstallprompt`, появится кнопка **INSTALL**. Она вызывает системный диалог установки. Доступность и момент появления события определяются браузером; при отсутствии кнопки можно воспользоваться меню Chrome «Установить приложение» или «Добавить на главный экран». После установки кнопка скрывается; при запуске в standalone-режиме тоже. При первом запуске после установки Android/Chrome формирует splash screen из имени, иконки и цветов манифеста — его внешний вид зависит от версии браузера и ОС.

### Альтернатива: local-web-server

`local-web-server` может отдавать файлы по HTTPS. Не запускайте его с корнем в проекте, где находится `certs`: иначе приватные ключи могут стать доступны по сети. Например, создайте отдельный каталог только с публичными файлами и запустите сервер из проекта:

```sh
mkdir -p /tmp/mesto-public
cp index.html log.html styles.css app.js log.js sw.js manifest.webmanifest /tmp/mesto-public/
cp -R assets /tmp/mesto-public/
npx --yes --package local-web-server ws --directory /tmp/mesto-public --https --key certs/server.key --cert certs/server.crt
```

После изменений файлов обновите копию `/tmp/mesto-public`. Самоподписанный сертификат, созданный автоматически lws, не заменяет описанные выше CA и сертификат с правильным SAN.

## Контакты

Контактный адрес находится в секции `contacts` файла `index.html`. Замените `hello@example.com` и соответствующий `mailto:` на свой адрес.

## Офлайн-работа и журнал

Service Worker предварительно кэширует оболочку, манифест, иконки и страницу `log.html`. Список эмодзи запрашивается из GitHub API с запасным вариантом из кэша; изображения эмодзи кэшируются по мере просмотра. Поэтому **для первого получения списка и каждого ещё не просмотренного эмодзи нужен интернет**. Изображения эмодзи загружаются по мере приближения к области просмотра с помощью `IntersectionObserver`, с резервным вариантом без него. После загрузки выбранные изображения и список доступны офлайн при наличии кэша браузера.

Откройте «Журнал SW» в боковом меню: `log.html` читает локальный IndexedDB-журнал событий `install`, `activate`, `fetch` и `cache`; доступны обновление и очистка. Хранится до 500 последних событий. Первый запрос страницы до активации Service Worker может не попасть в журнал. Браузер может очистить данные приложения при нехватке места или по запросу пользователя.

После изменения приложения увеличьте `VERSION` в `sw.js`, обновите страницу и закройте старые вкладки, если обновление задерживается. Проверка синтаксиса: `npm run check`.
